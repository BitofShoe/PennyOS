PennyOS first run

Get Penny talking.

This installed app starts Penny's local desktop shell. It does not include a model runtime or model weights. That is not a scam, it is the part where your computer gets to keep its own brain.

Quick Start

1. Start a local model server

Use LM Studio, llama.cpp, or another OpenAI-compatible local server. Penny expects one on loopback, usually address 127.0.0.1, port 1234, path /v1.

2. Load a chat model

The model must be loaded or exposed by the server. Seeing a model installed on disk is not the same thing as serving it.

3. Open PennyOS

Use the Start Menu shortcut or pennyos.exe. Penny opens her UI, checks the local server, and reports what she can actually see.

4. Pick lanes in Settings

Open Settings, then First-run local brain setup. Pick the chat model and tool model from the dropdowns, then save.

LM Studio Setup

LM Studio is the friendliest path for most Windows users. The basic loop is download LM Studio, download a model, load it, then start the local server.

  1. Install LM Studio for Windows.
  2. Open LM Studio and download an instruction-tuned chat model. Do not use an embedding-only model for chat.
  3. Load the model in LM Studio.
  4. Open LM Studio's Developer or Local Server area and start the API server.
  5. Use port 1234 unless you know you changed Penny's endpoint settings.
  6. Return to PennyOS Settings and press Refresh.

What Penny wants to see

/v1/models should list the loaded chat model. If the model list is empty, Penny can open, but model-backed chat will not be ready yet.

llama.cpp Setup

llama.cpp is more manual, but it works if you expose an OpenAI-compatible server and point Penny at it.

PENNY_LOCAL_LLM_BACKEND=llama_cpp
PENNY_LMSTUDIO_BASE=your loopback server base URL
PENNY_LOCAL_LLM_TRANSPORT=chat

The PENNY_LMSTUDIO_* names are historical. In this mode they mean "the local OpenAI-compatible endpoint Penny should use."

Keep chat and embeddings separate

Embedding models are useful for memory search, but they are not chat models. If you route chat to an embedding-only model, Penny may fail in extremely boring ways.

Picking Models

Good for Penny

  • Instruction-tuned chat models.
  • Models that fit your VRAM without constant swapping.
  • Vision-capable models if you want screenshot/image reactions.
  • A smaller fast tool model if you do lots of file/project work.

Bad fits

  • Embedding-only models as the chat lane.
  • Base models that were not tuned for chat.
  • Huge models your machine can barely load.
  • Models that refuse personality and become beige helpdesk sludge.

On this branch, Penny is built around OpenAI-compatible chat/tool lanes. She will honestly report readiness for the endpoint you already have running. She will not download, load, unload, or swap your models behind your back.

Feature Map

Chat

Talk normally, or give a bounded job. Specific asks work better than vague "be agentic" fog.

Memory

Explicit memory is local. Archive memory is review-gated before promotion. Embeddings help, but keyword fallback is expected.

Settings

Use First-run local brain setup to pick chat/tool lanes. Use diagnostics when Penny says the endpoint is not ready.

About voice

The old browser read-aloud voice is parked because it uses system voices, not Penny. Speaches/TTS sidecar controls are review experiments, not the real runtime voice yet.

FAQ

Does PennyOS include LM Studio, llama.cpp, or models?

No. The installed app includes Penny's desktop shell, bundled Penny server sidecar, public UI, seed memory, and runtime resources. You still need a local model endpoint for model-backed chat.

Why does the dropdown show so many models?

Penny shows what the configured runtime reports, plus saved/configured candidates. Loaded or exposed models are the plug-and-play choices. Installed-only models may still need to be loaded in LM Studio or served by llama.cpp.

Why is semantic memory sometimes "fallback"?

The embedding lane is optional. If the configured embedding model is missing or unloaded, Penny can still chat and use keyword fallback.

Will this cross wires with another Penny run?

The desktop package stores writable state in app data. Source/dev runs usually use checkout-local state. If both are open on the same port, one will lose. Run one Penny at a time unless you deliberately changed ports.
